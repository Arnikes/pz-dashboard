## Changes since v1.9.0

### Overview and Players

- Use **Customize** on Overview to add, hide, and reorder widgets. The browser
  saves the layout locally, and **Reset layout** restores the defaults.
- Locate online players from the roster and pan, zoom, or fit the map. Live
  positions use the bundled, optional `PZConsoleMap` v1.0.0 mod for Build 42.
  Install it on the game server and share the game cachedir with the panel.
  To draw the base map, also mount the game installation at `/server-files:ro`.
  See the [player map setup guide](https://github.com/Arnikes/pz-dashboard/blob/v1.10.0/docs/player-map.md).

### Maintenance, Console, and Events

- Schedule recurring in-game chat announcements through RCON, including in
  RCON-only mode. Scheduled restarts require a running local game container
  and use the existing player warning and graceful restart sequence. Both
  schedules are off by default, and their next due times survive a panel
  restart. See [periodic maintenance](https://github.com/Arnikes/pz-dashboard/blob/v1.10.0/docs/operations.md#periodic-chat-announcements-and-server-restarts).
- Follow the planned stages and current step of an operation, with clearer
  countdowns and more compact controls in Maintenance.
- Keep unsent Console input and distinguish RCON failures from unconfirmed
  outcomes. Any retry is manual. Log refreshes
  preserve the reading position and keep the last successful view available
  through temporary failures. Console audit events use a fixed summary to
  keep command arguments out of new records and displayed history.
- Scan Events by local date and severity in compact rows. Events and Telegram
  use severity for the Problems filter and subscription. The notification inbox
  preserves unread messages when filters change, and MTProxy reports clearer
  secret-format errors.

### Backups, configuration, and deployment

- See missing world data or configuration in a verified backup and review the
  selected archive before confirming a restore. Restore validates and stages the
  archive before stopping the game. Local archives remain available when S3
  listing fails.
  See [backups and restore](https://github.com/Arnikes/pz-dashboard/blob/v1.10.0/docs/operations.md#backups-and-restore).
- Keep pending draft edits safe during modpack imports. Background configuration
  verification leaves the editor available, while applying a configuration
  still locks concurrent changes.
- Preserve literal dollar signs in Compose values during image updates and
  detect unsupported Compose configurations before changing services.

### Upgrade notes

- Use `ghcr.io/arnikes/pz-dashboard:v1.10.0` for the panel image after
  publication. Keep the existing environment and persistent volumes. Pull and
  recreate only `pz-dashboard`, including both Compose files for an overlay.
  Update local builds and digest-pinned deployments from the host. See
  [released-image updates](https://github.com/Arnikes/pz-dashboard/blob/v1.10.0/docs/installation.md#released-images-from-ghcr)
  and [Maintenance self-update requirements](https://github.com/Arnikes/pz-dashboard/blob/v1.10.0/docs/installation.md#update-the-console-from-maintenance).
