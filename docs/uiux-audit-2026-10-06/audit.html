Комплексный UI/UX-аудит PZ Console

Хорошая основа: UX 28/40, техническое качество 14/20.
10 пунктов: P0 — 0; P1 — 1; P2 — 8; P3 — 1. Главный риск — потеря удобства и точности диагностики на телефоне.

НаходкиОхватПроверкиОценкиСнимкиРекомендации

Основной путь уверенный: выбрать профиль → подготовить черновик → проверить различия → подтвердить применение → проверить запуск. Проблемы возникают в стрессовом сценарии расследования сбоя: длинный digest ломает ширину, сжатие логов скрывает второй объект, а терминал обещает готовность. Системные причины — независимое вычисление состояния и UX-текста, недостаточная проверка естественных длинных tokens и слишком агрессивная нормализация диагностики.

P1 UX-01 · Длинные диагностические данные ломают мобильную ширину

Где
Обзор, События, ошибки списка Бэкапов
Категория
Адаптивность / восстановление после ошибки
Доказательство
При viewport 390px обычный SHA-256 в событии даёт document.scrollWidth=597px, Workshop URL — 443px. Ошибка списка с SHA-256 даёт 518px. В 320px также воспроизводится. На desktop 1440px digest и URL помещаются.
Воспроизведение
Открыть События на 390px. Передать событие type=error, text=Digest sha256: плюс 64 hex-символа. Открыть Обзор: то же событие показывается в последних событиях. Отдельно передать ok=false,error=64-символьный digest в Backups/Events.
Влияние
При диагностике сбоя текст выходит из карточки и появляется горизонтальная прокрутка всей страницы. Часть сообщения нельзя прочитать в обычной вертикальной навигации.
Рекомендация
Добавить overflow-wrap:anywhere к .event-row .e-text и .list-error, сохранить min-width:0. Не обрезать диагностический текст. Проверить SHA-256, Steam URL и пути на 320/390px.
Критерий
WCAG 2.2 SC 1.4.10 Reflow; проверка на 320 CSS px
Команда
$impeccable adapt

Где
Консоль → Логи контейнера
Категория
Достоверность диагностических данных
Доказательство
Две строки WARN Failed to load Workshop item 123456789 и WARN Failed to load Workshop item 987654321 отображаются как первая строка с × 2. Второй ID исчезает из интерфейса.
Воспроизведение

Что стоит сохранить

  • Визуальный язык соответствует PZ: тёплый уголь, бежевый текст, оливковые состояния и сдержанные красные опасные действия. Целостность реализации: PASS.
  • Черновик → файлы → запуск разделены; ревизии, маскировка секретов, явные подтверждения и проверка запуска снижают риск ошибочного применения.
  • Linked tabs, видимый фокус, Escape/Tab в диалогах и возврат фокуса, общая SSE-связь, retry и сохранение ввода редактора покрыты браузерными проверками.
  • Основные мобильные действия имеют 44px touch height; узкая вкладка Мир 28×44px сама по себе не нарушает AA-порог 24px с исключениями.
  • Основные непрозрачные текстовые токены на четырёх базовых поверхностях дают контраст не ниже 5,02:1. Это не проверка всех составных фонов/состояний.

Проверки, detector и ограничения

Матрица: Chromium, RU/EN, 320/390/768/1440×844; 64 рабочих route cases + 24 вход/справка/offline. Рабочие экраны наполнены вымышленными данными; язык и отсутствие skeleton проверены перед снимками. В обычных состояниях 0/88 document overflow и 0/88 зарегистрированных axe violations. Среди 93 axe captures (матрица + 5 stress/error) incomplete: aria-prohibited-attr 69, aria-valid-attr-value 69, color-contrast 85. Неполные проверки касаются generic regions/uptime, связи со скрытым dialog и select backgrounds; они требуют отдельной проверки, а не объявления WCAG-соответствия. Дополнительно проверены 24 realistic token cases, сетевой отказ входа и идентичность строк логов. 130 browser checks прошли: 124 существующих, 5 audit checks, 1 performance; затем 3 проверки наполненных снимков/доказательств. Итого 133 успешных выполнения. Наполненная матрица 88 случаев перепроверена. Измерение производительности относится к 60 одинаковым snapshots, CPU 4×, 200 архивам/100 событиям/5000 строкам логов: max 14,7 ms, 0 long tasks, 0 DOM mutations в восьми контейнерах. Это не LCP, TTI или скорость реального сервера. Физические устройства, touch gestures, экранная клавиатура, NVDA/VoiceOver, Safari/Firefox и реальные операции PZ не проверены.

Detector: 42 raw findings — 26 font-size, 8 color, 5 radius, 2 font, 1 em-dash. Пять явно отклонены: два Russo One (сохранённая совместимость, не используется текущим UI), black text в index (detector не разрешил relative CSS), белый текст danger button (задан DESIGN.md), тире/«—» в данных и placeholders. Остальные — advisory и небольшие отклонения шкал/токенов; это не 37 дополнительных UX-дефектов. Не рекомендую автоматически уменьшать мобильные 16px inputs или удалять намеренные shadow/overlay colors. Live overlay не установлен: IAB evaluate доступен только для чтения; надёжными доказательствами служат изолированные browser measurements и PNG.

Старые mobile full-page captures могут рисовать fixed navigation в середине длинного PNG; это не доказательство реального перекрытия. В текущем интерфейсе есть scrollbar вкладок и подсказка о горизонтальной прокрутке: скрытая в первом фрагменте История не записана как дефект. Неполный SSE в preview 8767 оставляет skeleton placeholders — это ограничение fixture, исключённое из findings.

Нормативные источники: WCAG 1.4.10 Reflow; WCAG 2.5.8: 24px и исключения; WCAG 1.4.1 Use of Color. Целевой размер 44px — рекомендация продукта; каждый элемент меньше 44px не является автоматически нарушением AA.

Критерии готовности: длинные события/ошибки не расширяют document на 320/390px; разные ID остаются различимы; RCON/Watchdog сообщения совпадают с действительным состоянием; empty/error состояния дают следующий шаг; transport error не заставляет повторно вводить пароль; font URLs больше не дублируют идентичный body.
